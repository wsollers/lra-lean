# What's Left Foundationally (`[RECAP]` of the project's own open-items list, reproduced for searchability)

[← Back to Index](00-index.md)

Governing chain position: Set → Relations → Equivalences → Maps/Functions/Operators → Order → Operations → Algebra.Structures → **Algebra.Models (Morphisms) [DONE, this document]** → Algebra.Signatures → NumberSystemTower → UniversalProperties.

**1. `Algebra.Signatures` — not yet built as its own interlude.** `FormalVocabulary`, `BasicArithmeticLanguage` (primitive/derived, operation/relation split), `Algebraic` (named signature subsets: MagmaSignature → FieldSignature), `Ordered`, `NumberSystem`. Distinct from Algebraic Structures ([`07-algebraic-structures.md`](07-algebraic-structures.md), which builds structures themselves) — this builds the formal *language* for talking about structures model-theoretically (`Signature`, `Model`, `Satisfies`). Per the project's own model-theory roadmap, ~80% reducible to existing `Logic.Signature/Model` machinery — mostly scaffolding, not new mathematics. **Now partially pre-built:** the equational fragment of this (`Law`, `Satisfies` for pure operation-identities) already exists in [`06-operations.md`](06-operations.md) §6.7.3, with the scope boundary against the wider model-theory layer drawn explicitly in [`06b-model-theory-boundary.md`](06b-model-theory-boundary.md). `Algebra.Signatures` should therefore generalize `Satisfies` from single-operation equational laws to full multi-symbol signatures with mixed relational content, not invent the concept from scratch.

**2. `NumberSystemTower` — the actual construction, largest remaining chunk.** $\mathbb N\to\mathbb W\to\mathbb Z\to\mathbb Q\to\mathbb R\to\mathbb C$, each exhibited as a genuine Model of the prior document's signatures; canonical embeddings; preservation-of-operations/order; characteristic; cardinality comparison (flagged as heavier than siblings, deliberately deferred until uncountability of $\mathbb R$ becomes load-bearing for measure-theoretic Brownian motion). **Largely pre-built already:** [`06a-satisfaction-certificates.md`](06a-satisfaction-certificates.md) contains the fully worked cert tree for ℕ/ℤ/ℚ/ℝ's algebraic laws via the transport theorems — `NumberSystemTower` should consume that file's cert tree directly (citing `Cert_Z_Add_Commutative_via_QuotientTransport` etc.) rather than re-deriving commutativity/associativity from scratch. What remains genuinely new for `NumberSystemTower` itself: the order-theoretic and completeness facts (which are explicitly *not* `Law(S)` certs, per §6b's boundary), canonical embeddings, and characteristic/cardinality.

**3. `UniversalProperties` — the capstone.** Initial objects, free objects, the quotient universal property (recognizing [`03-equivalences.md`](03-equivalences.md)'s factorization theorem and [`08-morphisms.md`](08-morphisms.md)'s First Isomorphism Theorem as instances of ONE categorical pattern), localization, field of fractions, completion property, and the sharpest form of the real-number characterization theorem (uniqueness of the complete ordered field).

**4. Lighter-weight open items, carried from the project's own notes.**
- `Set.ZFC` scope decision: whether to formalize ZFC *itself* as a first-order theory (its own Model/Semantics) — explicitly undecided, independent of everything else.
- `NumberSystemTower.CardinalityComparison`: deliberately deferred.
- [`09-congruences-placement.md`](09-congruences-placement.md)'s congruence forward-reference paragraph: low-cost documentation task, not yet executed.
- A distributivity-specific transport theorem (binary-law shape, relating two operators) is named but not yet stated in full in [`06-operations.md`](06-operations.md) §6.7.3 — flagged there as "structurally identical in proof pattern" to the existing transport theorems but not yet written out.

**Design decision recorded here for future reference.** The Operations/cert material was deliberately split into three files rather than kept as one — [`06-operations.md`](06-operations.md) (machinery), [`06a-satisfaction-certificates.md`](06a-satisfaction-certificates.md) (instances), [`06b-model-theory-boundary.md`](06b-model-theory-boundary.md) (scope policy) — specifically to prevent the machinery file from becoming "busy" as the number-system tower and eventual structure certs accumulate. Any future structure whose cert tree grows large should get its own `06x-*.md` sibling file rather than being appended to `06-operations.md` directly.

**Audit correction, folded in.** A real three-way audit against the live repo (see [`12-audit-corrections.md`](12-audit-corrections.md) and `audit-results.md` in project knowledge) found the `Law(S)`/`Satisfies` design originally proposed here was unnecessary — the repo already has a strictly more general mechanism (`Signature`/`Model`/`Equation`/`SatisfiesEquation`/`IsVariety`) in `LRA/UniversalAlgebra/Satisfaction/`. Files 6/6a/6b have been corrected accordingly. **This changes item 1 above materially:** `Algebra.Signatures` is not "not yet built" — its equational core substantially already exists; the real remaining work is two small transport lemmas plus one Birkhoff `sorry`, not a new interlude built from scratch. See [`12-audit-corrections.md`](12-audit-corrections.md) for the full list of what the audit confirmed as genuine gaps versus what turned out to be documentation drift.

**Files not yet re-audited.** The audit prioritized the operation-satisfaction machinery, algebraic structures, and morphisms in Round 1; Round 2 closed most of the remaining gap by checking [`01-set.md`](01-set.md) through [`08-morphisms.md`](08-morphisms.md) in full. Remaining unaudited: `09` through `12`'s own reasoning (these are documentation-of-documentation, not directly checkable against Lean code). See [`13-audit-round-2.md`](13-audit-round-2.md) for the Round 2 findings, folded into `01`, `03`, `05`, and `08` above.

**Round 2's confirmed near-term priorities (small, well-scoped, ranked by the audit itself):**
1. Write the closure-operator abstraction (Extensive + Monotone + Idempotent; fixed-points-form-a-complete-lattice) in `LRA/Order` — currently the single highest-value unblocking addition, since [`03-equivalences.md`](03-equivalences.md)'s refinement-lattice join cites a theorem that doesn't exist.
2. Decide the `MembershipSignature` question (build a real unifying wrapper over Set's typeclass+Model layers, or retire the name from docs/memory).
3. Formalize group-specific subgroup/kernel/normal-subgroup vocabulary as an instance of the existing Signature/Model machinery — real, small, currently entirely absent.
4. Package `Sym(S)`'s bijective subset as a bundled `Group` structure (the raw operations already exist and are proved associative/unital).
5. Track Order's missing `L_≤` model theory as its own item, separate from Relation's `L_R` layer (which is done).

**Honest bottom line.** Everything from Logic through Morphisms ([`01-set.md`](01-set.md) through [`08-morphisms.md`](08-morphisms.md)) is now built out as full rigorous interludes matching the project's pedagogical requirements (geometric intuition first, no skipped steps, full predicate logic, domain-accurate predicate names), and the Operations layer additionally now has a working generic satisfaction/cert mechanism with an explicit scope boundary. Everything at and after Number Systems still needs the full interlude treatment, and this is also exactly the boundary where the project's own foundational-gap detour (Kossak → Halbeisen–Krapf → Enderton → Tarski → Takeuti → Feferman → Olmsted → Thurston) sits, since NumberSystemTower is where set-theoretic fluency (functions as sets, ℤ-lattice cosets, quotient universal property) gets its real workout.
