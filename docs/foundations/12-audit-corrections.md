This file summarizes the corrections already applied to [`06-operations.md`](06-operations.md), [`06a-satisfaction-certificates.md`](06a-satisfaction-certificates.md), and [`06b-model-theory-boundary.md`](06b-model-theory-boundary.md), and records what the audit found but has **not yet** been folded back into the other files.

## 1. Corrections already applied

**`Law(S)`/`Satisfies` (§6.7.3) — discarded, replaced.** The audit found no `Law(S)` type anywhere in the repo, and determined it should not be built: `LRA/UniversalAlgebra/Satisfaction/Definition.lean` already has `Equation`, `SatisfiesEquation`, `EquationalTheory`, `ModelsOfEquationalTheory`, `IsVariety` — Signature-and-Model level (not bare-carrier-and-operation level), strictly more general, riding on the pre-existing `Logic.Signature`/`Term`/`evaluateTerm` machinery, and already a real (if one-`sorry`-from-complete) formalization of Birkhoff's HSP theorem. `06-operations.md` §6.7.3 has been rewritten to describe this real mechanism instead.

**Product/quotient transport theorems — confirmed genuinely missing, scope corrected.** Not a renaming issue: the repo has `productModel`/`piModel` and `quotientProjectionIsHomomorphism`/`Congruence`, which construct the relevant `Model`s, but no proved lemma of the shape "if every factor satisfies equation $e$, the product does too." This is real, small, unwritten work — a targeted lemma against `SatisfiesEquation` + `Product`, and separately against `SatisfiesEquation` + `Quotient`/`Congruence` — not a port of the discarded apparatus.

**Cert naming — survives, repointed.** The `Cert_*`/`StructCert_*`/`_via_*` naming convention is unaffected in spirit (still: name proved facts short and consistently; `StructCert_*` is always a conjunction, never a restated equation) but every cert now names a `SatisfiesEquation`/`ModelsOfEquationalTheory` fact, or a pointer into the already-mature `AlgebraicStructures/*` bundled-structure layer, rather than a fact about the discarded type.

**Equational/relational boundary (`06b`) — content confirmed correct, maturity claim corrected.** The Birkhoff-HSP-grounded routing table (trichotomy/order-compatibility/triangle-inequality/Archimedean → general model theory, not the equational fragment) is substantively right and required no mathematical correction. What changed: this project doesn't need to *build* that boundary's equational half from scratch — `IsVariety` already exists at full signature generality, ahead of what `06b` originally assumed the project's own scope would need to cover.

**`AlgebraicStructures/*` maturity — corrected upward, everywhere it's cited.** The audit found `LRA/AlgebraicStructures/` already has real, mostly sorry-free, granularly-organized directories for far more structures than `07-algebraic-structures.md`/`06a-satisfaction-certificates.md` assumed — including `CompleteOrderedField/`, `OrderedField/`, `OrderedGroup/`, `OrderedRing/`, `LinearlyOrderedGroup/`, `LinearlyOrderedRing/`, `Archimedean/`, and a full lattice family (`Lattice`, `BooleanAlgebra`, `DistributiveLattice`, `BoundedLattice`, `JoinSemilattice`, `MeetSemilattice`). `06a-satisfaction-certificates.md` §6 now flags this and recommends repointing structure certs at the existing bundled Lean structures directly rather than treating them as still-to-be-built conjunctions.

## 2. Confirmed genuine gaps (real work, not documentation drift)

- **Two small transport lemmas** (product-side, quotient-side) against `SatisfiesEquation` — see above.
- **`modelsOfEquationalTheoryIsVariety`** — the one remaining `sorry` closing Birkhoff's "←" direction in `UniversalAlgebra/Satisfaction/Definition.lean`.
- **Sorry debt in `LRA/Operation/Laws/*`** — all twelve law families (Associative, Commutative, Distributive, Identity, Inverse, Cancellation, Idempotent, Absorbing, Absorption, Nilpotent, Closure, QuotientCompatible) have sorry-free `Definition`/`Consequences` files but real debt in `Theorems`/`Relationships`/`FailureModes`. Heaviest: `Inverse` (26 sorries total), `Cancellation` (23), `Distributive` (9), `Absorbing` (9), `Identity` (9). `QuotientCompatible` has 3 sorries in `Definition.lean` itself — the one family with an incomplete *definition*, not just downstream theorems, worth prioritizing since everything above it may implicitly depend on it.
- **Morphism duplication — a real architecture decision, not a documentation gap.** `LRA/Morphism/Properties/*` (atomic preservation predicates: `PreservesBinaryOperation`, `PreservesRelation`, `ReflectsRelation`, `OperationEmbedding`, `RelationEmbedding`, `StructuralEmbedding`, etc.) and `LRA/UniversalAlgebra/{Homomorphism,Isomorphism,Embedding}/*` (bundled `Model S → Model S` structures) were confirmed, by direct import inspection, to be **genuinely independent formalizations of the same underlying idea** — `UniversalAlgebra/Homomorphism/Definition.lean` imports only `Satisfaction.Definition`, nothing from `LRA.Morphism`. This is not resolved by this document; it needs a real decision (rebuild one on top of the other, or explicitly document why both exist) before [`08-morphisms.md`](08-morphisms.md) can be corrected with confidence. Recorded here as open, not silently assumed resolved.
- **Stale path references in the repo's own self-audit docs.** `OMNIBUS-GAP-LIST.md` and `ISSUES.md` still reference the pre-flattening `LRA/VolumeI/...` namespace layout; the live repo has flattened `VolumeI/*` into top-level topic folders. The gaps those docs name may still be real, but their file-path pointers are stale and should not be trusted at face value.
