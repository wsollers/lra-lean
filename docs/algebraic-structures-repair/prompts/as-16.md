## Spec (given by the user)

Order-theoretic: a lattice `(L, ≤)` with a least element `⊥` and a greatest
element `⊤`. Algebraic: `(L, ∨, ∧, 0, 1)` — the standard lattice axioms
(idempotence, commutativity, associativity, absorption) plus
`x∨0=x, x∧0=0` (bottom) and `x∧1=x, x∨1=1` (top). Noted: under this framing
`(L,∨,0)` and `(L,∧,1)` are each commutative monoids. Standard examples:
power set `(𝒫(X), ∪, ∩, ∅, X)`, divisor lattice `(𝒟_n, lcm, gcd, 1, n)`,
extended reals `(ℝ̄, max, min, -∞, +∞)`.

## Audit

`BoundedLatticeLaws join meet bottom top := LatticeLaws join meet ∧
TwoSidedIdentity join bottom ∧ TwoSidedIdentity meet top`. This states only
**half** of each bound's two conditions as an axiom — `bottom` as
join-identity (`0∨x=x`), `top` as meet-identity (`1∧x=x`) — not the
"absorbing" halves (`x∧0=0`, `x∨1=1`) the user's spec lists separately.

Verified by hand this is **not a gap**: the absorbing halves are provable
consequences of the stated halves plus `LatticeLaws`'s own absorption law.
Concretely, absorption gives `0 ∧ (0 ∨ x) = 0`; substituting the given
`0 ∨ x = x` turns this into `0 ∧ x = 0` directly (and `x ∧ 0 = 0` by
commutativity). The dual argument gives `x ∨ 1 = 1` from `1 ∧ x = x` and
absorption the other way. So the current definition is a non-redundant,
logically complete axiomatization of the user's four conditions — content
was already correct, no fix needed. Documented this derivation directly in
the new doc comment so it doesn't need re-deriving next time someone reads
this file.

## A syntax error worth remembering

Placing a doc comment directly before a `variable {n : Nat}` command failed
to parse (`unexpected token 'variable'; expected 'lemma'`) — Lean 4 doc
comments can only precede actual declarations (`def`/`theorem`/`structure`/
etc.), not `variable`. Fixed by moving the `variable` command before the doc
comment, attaching the doc to the first real declaration (`Divisors`)
instead.
