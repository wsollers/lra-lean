# as-02 — Semigroup

**STATUS: done, 2026-08-26.**

## What was found and fixed

`MultiplicativeSemigroupLaws` had the exact same gap as `MagmaLaws` did (as-01):
only `MulAssociative`, no `Nonempty R`. The user's own definition states it
explicitly ("S is a non-empty set"), and the reasoning is identical to Magma — no
identity element yet to derive nonemptiness for free. Fixed by adding
`CarrierNonempty : Nonempty R` to the class.

That fix surfaced a second, independent problem: a shared file,
`AlgebraicStructures/MathlibBridge.lean`, already had
`instance {R}[Semigroup R] : MultiplicativeSemigroupLaws R where MulAssociative :=
mul_assoc` — a duplicate of the per-structure bridge this item was about to add, now
also missing `CarrierNonempty`. Removed the old instance from the shared file (left a
comment pointing at its new home) and added an import from `MathlibBridge.lean` to
`Semigroup/Constructions/Mathlib/Laws.lean` so nothing downstream lost the instance.
This confirms the per-structure `Constructions/Mathlib/` convention is the right
target to migrate *away from* the old shared `MathlibAdapters.lean`/`MathlibBridge.lean`
files, tier by tier, rather than letting both exist in parallel — worth keeping in
mind for tiers 2+, where the same shared files likely hold more instances that will
need the same treatment as their subject comes up in the queue.
