# as-12 — Lattice

**STATUS: done, 2026-08-26.**

## Spec (given by the user)

Order-theoretic: `(P, ≤)` a poset where every pair has both a join and a
meet — equivalently, simultaneously a join-semilattice and a meet-semilattice.
Algebraic: `(L, ∨, ∧)`, non-empty, with four identities — idempotent,
commutative, associative (each for `∨` and `∧` separately), plus mutual
absorption (`x ∨ (x ∧ y) = x`, `x ∧ (x ∨ y) = x`). Equivalence stated both
directions. Standard examples: power sets under union/intersection,
divisibility on positive integers (join = lcm, meet = gcd), any total order
(join = max, meet = min).

## Audit

`LatticeLaws join meet := JoinSemilatticeLaws join ∧ MeetSemilatticeLaws meet
∧ MutualAbsorptionLaw join meet`. Unfolding `MutualAbsorptionLaw` (`Absorption
Law join meet ∧ AbsorptionLaw meet join`, i.e. `(∀x y, join x (meet x y) = x)
∧ (∀x y, meet x (join x y) = x)`) confirms this is **exactly** the user's four
algebraic identities — idempotent+commutative+associative for `∨` (from
`JoinSemilatticeLaws`), same for `∧` (from `MeetSemilatticeLaws`), and both
absorption laws. No gap, no fix needed — content was already correct, just
relocated with a real doc comment (the original was unfilled `TODO`
boilerplate).

## Important finding: the algebra↔order bridge already exists

Unlike `JoinSemilattice`/`MeetSemilattice`, which each needed a brand-new
`Constructions/OrderTheoretic/InducedOrder.lean` built from scratch (as-08/09),
`Lattice`'s algebra↔order equivalence **already exists**, pre-built, at
`LRA/Order/Interop/AlgebraicLattice.lean`:

- `OrderFromJoin`/`OrderFromMeet` — the two induced-order relations (same
  shape as `JoinSemilattice`/`MeetSemilattice`'s own `InducedOrder`).
- `AlgebraicLatticeJoinOrderIsOrderLattice` /
  `AlgebraicLatticeMeetOrderIsOrderLattice` — algebra → order, both
  directions (join-based and meet-based).
- `OrderLatticeOperationsAreAlgebraic` — order → algebra, the *other*
  direction, which neither semilattice's own bridge built.

This is actually **more complete** than either semilattice's one-directional
bridge. Already `sorry`'d throughout (consistent with D8), pre-existing, and
lives **outside** the `LRA/AlgebraicStructures/Lattice` validator target (it's
under `LRA/Order/Interop/`). Did **not** duplicate this inside
`AlgebraicStructures/Lattice/Constructions/` — only fixed its one stale import
(`.Laws.Definition` → `.Interface.Laws.Definition`) as a downstream consumer.
Left its content and `TODO`-stub doc comments untouched — cleaning those up is
outside this item's own audit/reorg scope (that file isn't part of the
`AlgebraicStructures/Lattice` subject tree being reorganized).
