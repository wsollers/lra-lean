# as-07 — DiscreteInteger

**STATUS: done, 2026-08-26.**

## Spec (given by the user)

Three equivalent characterizations of ℤ:

1. **Two-sided Peano / System SP** — `(ℤ, 0, S, P)`: invertibility
   (`P(S(x))=x`, `S(P(x))=x`), acyclicity (`∀x, ∀n>0, Sⁿ(x)≠x`), discreteness
   via bidirectional induction (the only `S`/`P`-closed, `0`-containing subset
   is all of `ℤ`).
2. **Universal algebra** — the free group on one generator (infinite cyclic);
   every non-zero subgroup is `nℤ`.
3. **Model-theoretic / ordered ring** — a discretely ordered commutative ring
   with no zero divisors, gap law (`¬∃x, 0<x<1`, equivalently every element
   has an immediate successor `x+1`/predecessor `x-1`), Presburger
   quantifier-elimination completeness.

## Audit — a real bug found (same D2 category as Magma's as-01 correction)

`DiscretenessLaw.SuccAperiodic` read:

```lean
SuccAperiodic : ∀ n : Nat, 0 < n → SuccIterate n (0 : R) ≠ 0
```

— acyclicity checked **only at the basepoint `0`**. The user's own axiom 2
states it universally: `∀ x ∈ ℤ, ∀ n ∈ ℕ_{>0}, Sⁿ(x) ≠ x`. These are different
statements: the basepoint-only version typechecks and looks plausible, but
without additional additive structure nothing forces `0`'s aperiodicity to
transfer to every other element of `R`. (In the actual intended model, `Succ`
is literally `+1`, so `Sⁿ(x) = x + n`, and `Sⁿ(x)=x ⟺ n=0` regardless of `x` —
the two statements happen to coincide *there* — but `DiscretenessLaw` is
declared generically over `[HasSuccessor R] [HasPredecessor R] [OfNat R 0]`,
with no `Add`/`SuccessorAdditionLaw` in scope, so nothing in the class's own
hypotheses lets you derive the general statement from the basepoint one.)

Fixed: `SuccAperiodic` (the class field, and its restated `Wrappers`-section
theorem of the same name) now reads
`∀ (x : R) (n : Nat), 0 < n → SuccIterate n x ≠ x`, matching the spec verbatim.

Also reviewed, not a bug: `SuccessorLaws`'s `SuccInjective`/`PredInjective`
fields are provable consequences of the two invertibility fields
(`PredSucc`/`SuccPred`) rather than independent axioms — true, and kept as
bundled fields for interface convenience (documented in the new doc comment),
not something to remove.
