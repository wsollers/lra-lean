# as-06 — Archimedean

**STATUS: done, 2026-08-26** (with one deliberately deferred piece — see below).

## The D6 shape question, resolved

`Archimedean` had no `Laws/` subfolder at all before this item — just a flat
`Definition.lean`. Resolution: it doesn't get an `Interface/Definitions/`
folder either. Every other reorged subject (Magma, Semigroup, ...) introduces a
genuinely new *operation* (a `ConceptSignature` naming an interpreted-operation
bundle); Archimedean introduces no new operation at all — it's a *property* of
an already-existing `(Add, LT, OfNat 0)` signature, exactly like
`MultiplicativeOrderCompatibilityLaws`/`AdditionRespectsOrderLaws` elsewhere in
the tree, which also live directly in a `Laws/Definition.lean` with no
`Definitions/` folder of their own. So the shape here is just
`Interface/Laws/Definition.lean`.

## Audit

The user supplied five different rigorous formulations of "Archimedean" across
different algebraic contexts (ordered groups/additive structures, ordered
fields, lattice-ordered groups, commutative semigroups via divisibility, valued
fields via Ostrowski). Checked which one `ArchimedeanLaw` actually states:
`∀ x > 0, Cofinal (<) (Multiples x)`, and `Cofinal (<) S := ∀ point, ∃ y ∈ S,
point < y`. Unfolding: `∀ x > 0, ∀ point, ∃ n, point < IteratedSelfSum n x` —
this is exactly formulation #1/#2 (ordered groups / ordered fields: "for `a >
0`, eventually `n·a > b`"), which is also the formulation the rest of the
codebase already uses it for (`NumberSystems/Interface/ModelTheory/
LStructure.lean`'s `ArchimedeanDenseOrderedFieldExtensionImpliesArchimedeanLaw`,
for ordered fields specifically). The other four formulations (lattice-ordered
groups' infimum condition, commutative semigroups' divisibility condition,
valued fields' unbounded-valuation condition) are different mathematical
settings — restating the class to somehow cover all five would conflate
distinct concepts under one name, not correct anything. Content confirmed
correct, moved unchanged.

One naming quirk noted but not a bug: `IteratedSelfSum` is one-indexed
(`IteratedSelfSum 0 x = x`, i.e. `1 • x` in Mathlib `nsmul` terms, not `0 • x =
0`). Harmless for the cofinal property — `0` is never a useful witness except
when `point < 0`, and `IteratedSelfSum 0 x = x` already handles that case since
`point < 0 < x`.

## What was built

- `Interface/Laws/Definition.lean` — moved unchanged (`IteratedSelfSum`,
  `Multiples`, `ArchimedeanLaw`, wrapper theorem still `sorry`).
- `Constructions/Mathlib/Laws.lean` — a real bridge from Mathlib's own
  `Archimedean` class (for ordered additive commutative monoids). This one
  needed actual proof work, not a one-line citation: a reindexing lemma
  (`IteratedSelfSum n x = (n + 1) • x`, by induction against `succ_nsmul`) and
  a strict-vs-non-strict adaptation (Mathlib's `arch`/`exists_lt_nsmul` gives
  `≤`, ours needs `<` — resolved by taking one extra copy of `x`, which is
  already what `IteratedSelfSum`'s witness naturally provides). Both proved,
  not `sorry`'d — this is structural glue connecting two representations of
  "multiples," not the subject's own pedagogical content, same category as the
  other `Constructions/Mathlib` bridges in this tree.
- `Examples/Integers.lean`, `Examples/Rationals.lean` — `ArchimedeanLaw ℤ`/`ℚ`
  both come for free via the Mathlib bridge, once the right concrete-instance
  file (`Mathlib.Algebra.Order.Archimedean.Basic`) is imported (this is where
  Mathlib actually registers `Archimedean` instances for `ℤ`/`ℚ`/`ℝ` — the
  `Archimedean.Defs` file that defines the *class* doesn't include instances).

## Deliberately deferred

The user's spec discussed non-Archimedean counterexamples prominently (`ℝ(x)`
with an infinite element, hyperreal fields, `p`-adic absolute values). Building
any of these from scratch is real new construction (a full ordered field or
valued field), not a reorg/audit action, so none was built this item. A much
more tractable non-Archimedean example exists if wanted later — the
lexicographically-ordered group `ℤ ×ₗ ℤ` (via Mathlib's `Prod.Lex`), where
multiples of `(0, 1)` never exceed `(1, 0)` — flagged in the ledger for a
follow-up rather than silently skipped.
