# as-11 — AdditiveMonoid

**STATUS: done, 2026-08-26.**

## Spec (given by the user)

`(M, +, 0)`: non-empty carrier, closed associative `+`, two-sided identity
`0`. Formally identical to `Monoid` but additive convention. Key properties:
uniqueness of `0`, no additive inverses required (that's `AdditiveGroup`),
optional commutativity (additive commutative/abelian monoid — not yet a
subject in this tree), optional cancellativity (not built — new math, out of
scope for a reorg/audit pass). Standard examples: `(ℕ,+,0)`,
`(ℝ_{≥0},+,0)`, extended reals `([0,∞],+,0)` with `x+∞=∞+x=∞`, square
matrices under addition, and the free additive monoid on `{1}` (explicitly
the same object as `(ℕ,+,0)`, just a different framing — "generated freely by
`{1}` under repeated addition").

## Audit

`AdditiveMonoidLaws R := AdditiveSemigroupLaws R, AdditiveIdentityLaws R` (a
`class abbrev`, `[Nonempty R]` per D7) — the exact dual of `Monoid`'s
`MonoidLaws`. Matches the user's `(M, +, 0)` definition exactly. Content was
already correct pre-session — no fix needed, just relocated with real doc
comments.

## Reorg

Unlike `Monoid`, this subject was **fully flat** going in — no `Interface/`
folder at all yet (no partial `Signature`/`ModelTheory` split like `Monoid`
had). Straightforward mirror of `Monoid`'s `Interface/{Definitions,Laws}`
shape. No `Interface/ModelTheory/` folder built — it never had one, and
building one from scratch would be new content, out of scope per D4 (matches
`JoinSemilattice`/`MeetSemilattice`/`DiscreteInteger`'s precedent of not
having one either — only `Monoid` happened to have one pre-built before its
own item started). Deleted 11 empty stub files (same set as `Monoid`'s).

  `Monoid`'s own bridge (see `as-10.md`): did not treat the pre-existing,
  unsorried `MathlibBridge.lean` combining instances as precedent for this
  new item's bridge, even though the combination is equally "trivial."
- `Examples/` — 4 files covering all 5 named examples:
  - `NaturalNumbersWithZero.lean` — free via `Nat`'s Mathlib `AddMonoid`
    instance (needs `Mathlib.Algebra.Group.Nat.Defs`, same import gotcha as
    `Monoid`'s multiplicative version). Doc comment also covers the
    free-additive-monoid-on-`{1}` framing as the *same* object, per the
    user's own framing — no separate file built for it.
  - `NonNegativeReals.lean` — Mathlib's own `NNReal` type, free via the
    bridge.
  - `ExtendedReals.lean` — Mathlib's own `ENNReal` type, free via the bridge
    (`x + ∞ = ∞` holds by construction there).
  - `SquareMatricesUnderAddition.lean` — `Matrix n n ℝ` via `Mathlib.
    LinearAlgebra.Matrix.Defs`. Notably **simpler** than `Monoid.Examples.
    SquareMatrices`: matrix addition is just pointwise `Pi` addition on the
    entries, so it needs no `Fintype`/`DecidableEq` on the index type at all
    (unlike matrix multiplication, which does) — works for any index type
    `n`, not just `Fin n`.
- `Failures/PositiveNaturalsHaveNoIdentity.lean` — dual of `Monoid.Failures.
  PositiveIntegersHaveNoIdentity`, reusing `AdditiveSemigroup.Examples.
  PositiveNaturalsUnderAddition`'s existing `PositiveNaturals` subtype
  directly. `sorry`'d per D8. Added a `VolumeVIExamplesFailures.lean` import
  for `AdditiveMonoid.Failures`.
