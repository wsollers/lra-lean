# as-10 — Monoid

**STATUS: done, 2026-08-26.**

## Spec (given by the user)

`(M, *, e)`: non-empty carrier, closed associative `*`, two-sided identity
`e`. Key properties noted: uniqueness of identity, no inverses required
(that's `Group`), optional commutativity (`CommutativeMonoid`), and a
divisibility preorder `x ⪯ y ↔ ∃z, x*z=y` induced by every monoid (not built —
new math content, out of scope for a reorg/audit pass). Standard examples:
`(ℕ,+,0)`, `(ℕ,×,1)`, the free monoid on strings `(Σ*, ·, ε)`, the
transformation monoid `(Fun(S,S), ∘, id_S)`, and square matrices
`(M_n(ℝ), ×, I_n)` (noncommutative for `n≥2`).

## Audit

`MonoidLaws R := MultiplicativeSemigroupLaws R, MultiplicativeIdentityLaws R`
(a `class abbrev`, `[Nonempty R]` per D7) — closure is free from `Mul`,
associativity + nonemptiness come from the `Semigroup` parent,
`MultiplicativeIdentityLaws` gives the two-sided identity (`OneMul`/`MulOne`)
with `e` realized as `OfNat R 1`. This matches the user's `(M, *, e)`
definition exactly. Content was already correct pre-session — no fix needed,
just relocated with real doc comments (the originals were unfilled
`TODO`-stub boilerplate, same as every other subject so far).

## What was built

- `Constructions/Set/ClosedSubset.lean`: `ClosedSubsetOfNat` +
  `ClosedSubsetNonempty` (data — a `Nonempty` witness built from an explicit
  element, same as every prior example's `Nonempty` instances in this tree,
  never `sorry`'d anywhere; renamed from `def` to `theorem` per Lean's own
  def-of-a-`Prop` linter, not a content change) + `ClosedSubsetMonoidLaws`
  (real theorem, `sorry`'d). Differs from `Semigroup`/`CommutativeSemigroup`'s
  builders: nonemptiness comes directly from the identity-membership witness
  (`1 ∈ S`) rather than a separate ambient `[Nonempty {x // x ∈ S}]`
  hypothesis, since a submonoid always has that witness available for free.
- `Constructions/Mathlib/Laws.lean`: `instance [_root_.Monoid R] [Nonempty R]
  : MonoidLaws R`, `sorry`'d. Deliberately **not** written as `:= ⟨⟩` despite
  `MonoidLaws` being a zero-new-content `class abbrev` combination of two
  already-instance-registered atomic laws (one via `Semigroup`'s own bridge,
  one via the shared `MathlibBridge.lean`) — D8's own text calls out exactly
  this "it's just glue, not a real proof" rationalization as the specific
  mistake that got corrected twice before, so treated as in-scope for `sorry`
  even though it looks textbook-trivial. The pre-existing, untouched (tier
  4+, predates this repair process) `MathlibBridge.lean` uses unsorried
  `:= ⟨⟩` for its own combining instances (`SemiringLaws`, `RingLaws`,
  `FieldLaws`, etc.) — did **not** treat that as precedent for this new item.
- `Examples/` — all 5 of the user's standard examples:
  - `NaturalNumbersUnderAddition.lean` — wrapper struct, `sorry`'d. The
    monoid completion of `Semigroup.Examples.NaturalsUnderAddition`: same
    carrier/operation, now including `0`.
  - `NaturalNumbersUnderMultiplication.lean` — free via the generic Mathlib
    bridge, once `Mathlib.Algebra.Group.Nat.Defs` is imported for `Nat`'s own
    `Monoid` instance (`Mathlib.Algebra.Group.Defs` alone only defines the
    `Monoid` *class*, not `Nat`'s instance of it — a real debugging detour).
  - `FreeMonoidOnWords.lean` — `List Alphabet` wrapped in a fresh `Words`
    struct, specifically to avoid duplicating `Semigroup.Examples.
    NonemptyListsUnderConcatenation`'s own bare `Mul (List Alphabet)`
    instance on the *same* ambient type (a real global-instance collision
    risk once both files load together, e.g. via `VolumeVIExamplesFailures.lean`).
  - `TransformationMonoid.lean` — `S → S` under composition, wrapper struct,
    `sorry`'d.
  - `SquareMatrices.lean` — free via the Mathlib bridge, once
    `Mathlib.Data.Matrix.Mul` + `Mathlib.Data.Real.Basic` are imported for
    the actual `Semiring`/`Monoid` instances on `Matrix` — `Mathlib.Data.
    Matrix.Basic` alone does **not** provide `Mul`/`Monoid` on `Matrix`,
    another real debugging detour.
- `Failures/PositiveIntegersHaveNoIdentity.lean` — **the first `Failures/`
  folder actually built anywhere in this whole repair process.** D3 planned
  this pattern from the start ("a semigroup with no identity ... is exactly
  Monoid's failure mode"), and `Semigroup.Examples.PositiveIntegersUnderAddition`'s
  own doc comment even flagged it in advance ("it becomes Monoid's own
  `Failures/` example once that item comes up") — but no prior item,
  including `Semigroup` itself, had actually realized it yet. Reuses
  `Semigroup.Examples.PositiveIntegersUnderAddition`'s existing
  `PositiveIntegers` subtype directly rather than restating it. `sorry`'d per
  D8. Added a `VolumeVIExamplesFailures.lean` import for `Monoid.Failures` —
  that file had never imported any subject's `Failures/` before now.
