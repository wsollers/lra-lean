# as-15 — CommutativeMonoid

**STATUS: done, 2026-08-26.**

## Spec (given by the user)

`(M, *, e)`: closed associative `*`, two-sided identity `e`, commutativity.
Sits between `CommutativeSemigroup` and `AbelianGroup`. Key properties:
unique identity, no inverses required, and a divisibility preorder
`x ⪯ y ↔ ∃z, x*z=y` compatible with the operation (not built — new math,
out of scope). Standard examples: `(ℕ,+,0)`, `(ℕ,×,1)`, `(𝒫(S),∪,∅)`,
`(𝔹,∧,True)`.

## Audit

`CommutativeMonoidLaws R := MultiplicativeSemigroupLaws R,
MultiplicativeIdentityLaws R, MultiplicativeCommutativeLaws R` (`[Nonempty R]`
per D7) — exactly the user's four axioms (closure+associativity from
`Semigroup`, identity, commutativity). No bug found — matches the pattern of
every `Monoid`-family audit so far (`Monoid` as-10, `Group` as-13) also
finding no issue. Content unchanged, just relocated with a real doc comment.

## Reorg

Fully flat going in, no partial `Interface/` split (unlike `Monoid`/`Group`).
Straightforward mirror of `Monoid`'s `Interface/{Definitions,Laws}` shape.
`CommutativeMonoidConceptSignature` stays a literal `abbrev :=
MonoidConceptSignature` — commutativity is `Laws`-level content, not a new
signature element, so there's nothing to add at the UA-signature level. No
`ModelTheory` folder built (never had one).

## What was built

- `Constructions/Set/ClosedSubset.lean` — `ClosedSubsetCommutativeMonoidLaws`,
  `sorry`'d. Unlike `Group`'s own builder (as-13), **no ambient-hypothesis
  subtlety here** — a commutative-monoid-shaped closed subset of a
  commutative monoid is always itself one (no "unit of a non-group ambient"
  complication the way nonzero-reals-under-multiplication was for `Group`),
  so `[CommutativeMonoidLaws A]` on the ambient is the correct hypothesis,
  not overly strong.
- `Constructions/Mathlib/Laws.lean` — `instance [_root_.CommMonoid R]
  [Nonempty R] : CommutativeMonoidLaws R`, `sorry`'d per D8.
- `Examples/` — all 4 of the user's standard examples:
  - `NaturalNumbersUnderAddition.lean` — reuses `Monoid.Examples`' wrapper
    carrier directly, adds `MultiplicativeCommutativeLaws` on top. Same reuse
    pattern as `CommutativeSemigroup`'s own as-03 item promoting `Semigroup`'s
    carrier.
  - `NaturalNumbersUnderMultiplication.lean` — free via `Nat`'s Mathlib
    `CommMonoid` instance.
  - `PowerSetUnderUnion.lean` — fresh wrapper struct (`Mul := ∪`, `OfNat _ 1
    := ∅`), `sorry`'d — distinct from `CommutativeSemigroup.Examples.
    Semilattices.UnionSemilattice`, which has no identity component (that one
    only needed `CommutativeSemigroupLaws`, not the monoid version).
  - `BooleanConjunction.lean` — `(𝔹, ∧, True)`, free via Mathlib's **existing**
    `BooleanRing Bool` instance (`Mathlib.Algebra.Ring.BooleanRing` — already
    gives `Bool` a full `CommRing`, hence `CommMonoid`, under `Mul := and`/
    `One := true`). A genuine find, not built from scratch — worth
    remembering to check for existing Mathlib instances before assuming a new
    example needs a from-scratch wrapper.
- **No `Failures/` built** — same reasoning as `Lattice` (as-12): no equally
  cheap, already-sitting-in-a-tier-below-`Examples` failure mode specific to
  commutativity was identified (a non-commutative-monoid failure example
  would need more setup than the reuse-driven `Failures/` content built
  elsewhere this session).
